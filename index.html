GitHub Action · OpenCode agent

opencode-action —
OpenCode エージェントを GitHub Actions で動かす

dceoy/opencode-action は、AI コーディングエージェント OpenCode を GitHub Actions のジョブとして実行する composite action です。PR の差分へのインラインコメントに /opencode（または /oc）と書くだけでエージェントが起動し、説明・修正提案・コード変更までをその場で行います。手動 dispatch の汎用タスクと、pr-loop の pr-review skill を使った隔離環境での自動 PR レビューにも対応します。

01Quick start — 3ステップ

最小構成は「secret を1つ登録 → workflow を1ファイル追加 → PR の差分にコメント」の3つだけです。

1. Provider secret を登録する

リポジトリの Settings → Secrets and variables → Actions に、使うモデルプロバイダの API key を登録します。下の例では OpenCode の OPENCODE_API_KEY を使います（プロバイダごとの対応表はModels & secrets）。

2. Workflow を追加する

.github/workflows/opencode.yml
---
name: OpenCode
on:
  pull_request_review_comment:
    types: [created]
permissions:
  contents: read
  issues: write
  pull-requests: write
  id-token: write
jobs:
  opencode:
    if: contains(github.event.comment.body, '/oc') || contains(github.event.comment.body, '/opencode')
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1  # v7.0.1
        with:
          persist-credentials: false
      - name: Run OpenCode
        uses: dceoy/opencode-action@cda16d479232f0998a3046425dc43747f1c4c66e  # v1.1.0
        env:
          OPENCODE_API_KEY: ${{ secrets.OPENCODE_API_KEY }}
          GITHUB_TOKEN: ${{ github.token }}
        with:
          model: opencode-go/kimi-k3

デフォルト構成では、workflow の OIDC トークンを OpenCode GitHub App のトークンと交換するため id-token: write が必要です。action 参照はタグではなくフルコミット SHA にピン留めするのがこのリポジトリの流儀です。

3. PR の差分にインラインコメントを書く

PR review comment
/opencode explain this change

# 短いトリガーも使えます
/oc suggest a fix

エージェントがそのコメントスレッドに返信します。トリガー語は mentions input（デフォルト /opencode,/oc）で変更できます。

02動作の流れ

コメントから返信までの5段階です。各ステップを選ぶと詳細が切り替わります。

v2 の資格情報の扱いが要点です。 デフォルト（OIDC）モードでは GitHub の資格情報は OpenCode の環境に渡されず、gh は未認証で動きます。ランチャーだけが最終メッセージをレビューコメントのスレッドへ返信として投稿します。コードを書かせる（git push させる）場合は use-github-token: true ＋ checkout 資格情報の永続化 ＋ 書き込み可能なトークンが必要です。

03使い方の3形態

直接 action を呼ぶ方法と、呼び出し側が小さく済む reusable workflow が2つ用意されています。

基本形

自分の workflow の step から uses: dceoy/opencode-action@<SHA> で直接呼びます。上の Quick start がこの形です。トリガー（review comment / dispatch / 任意イベント）、権限、checkout の有無をすべて自分で制御したい場合に使います。

  • workflow_dispatch で直接使う場合も workflow_call と同じ inputs が使え、model と空でない prompt が実行条件です。
  • 出力は opencode-version、runtime（v1/v2）、cache-hit の3つ。

Reusable workflow

/opencode・/oc のインライン PR レビューコメント、手動 dispatch、固定 prompt による任意イベント向けの汎用 bot です。レビューコメントは OWNER / MEMBER / COLLABORATOR のコメントで、かつ mentions の語句を含む場合だけ受理されます（model を渡してもこの条件は回避できません）。コメント以外のイベントでは空でない prompt が必須です。

caller workflow
---
name: OpenCode
on:
  pull_request_review_comment:
    types: [created]
jobs:
  opencode:
    permissions:
      contents: read
      issues: write
      pull-requests: write
      id-token: write
      actions: read
    uses: dceoy/opencode-action/.github/workflows/opencode-bot.yml@cda16d479232f0998a3046425dc43747f1c4c66e  # v1.1.0
    with:
      model: opencode-go/kimi-k3
    secrets:
      OPENCODE_API_KEY: ${{ secrets.OPENCODE_API_KEY }}

v2 では bot が返信を投稿するのは pull_request_review_comment イベントのときだけです。workflow_dispatch と固定 prompt の実行ではランチャーは何も投稿しません。

Reusable workflow review-only

pull_request イベントで自動レビューを行います。dceoy/pr-loop の外部 pr-review skill を SHA ピン留めでインストールし、隔離された review-only 環境で実行します（詳細はPR reviews）。デフォルトモデルは当面無料の opencode/deepseek-v4.1-flash-free で、プロバイダの API key なしで試せます。

caller workflow
---
name: OpenCode review
on:
  pull_request:
    types: [opened, reopened, synchronize, ready_for_review]
jobs:
  review:
    permissions:
      contents: read
      issues: write
      pull-requests: write
      id-token: write
      actions: read
    uses: dceoy/opencode-action/.github/workflows/opencode-review.yml@cda16d479232f0998a3046425dc43747f1c4c66e  # v1.1.0

信頼できる同一リポジトリの PR を前提とした例です。公開フォークからの PR では GitHub が secrets を渡さず GITHUB_TOKEN も読み取り専用になります（Dependabot PR も同様）。

04Models and secrets

model input は provider/model 形式で指定し、対応する API key を secret として渡します。プロバイダ側のアカウントに十分なクレジット／クォータが必要です。

Providerモデルの例Secret

OpenRouteropenrouter/openrouter/freeOPENROUTER_API_KEY

OpenAIopenai/gpt-5.6-solOPENAI_API_KEY
Sakura AI Engine（同梱済み）sakura/gpt-oss-120bSAKURA_AI_ENGINE_API_KEY
Custom providermyprovider/my-modelプロバイダ固有

Reusable workflows は上記に加えて GOOGLE_GENERATIVE_AI_API_KEY、DEEPSEEK_API_KEY、XAI_API_KEY、GROQ_API_KEY、CEREBRAS_API_KEY、MOONSHOT_API_KEY も secret として受け付けます。選んだモデルに必要な secret だけを渡してください。

Custom providers

OpenCode に組み込まれていないプロバイダ（多くは OpenAI 互換 API）は、リポジトリルートの opencode.json で定義できます。Sakura AI Engine は例外で、同梱 toolkit に sakura プロバイダとして設定済みのため、通常は opencode.json 不要で sakura/* モデルが使えます。

opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My Provider",
      "options": {
        "baseURL": "https://api.example.com/v1",
        "apiKey": "{env:MYPROVIDER_API_KEY}"
      },
      "models": {
        "my-model": { "name": "My Model" }
      }
    }
  }
}

プロジェクト側の provider 設定は「信頼済み入力」として扱ってください。 設定は baseURL やリクエストヘッダを制御できるため、信頼できない変更が入ると資格情報が別エンドポイントへ送られかねません。workflow のトリガーと secret へのアクセスを適切に制限してください。なお review-only 実行ではプロジェクト設定は無効化されるため、カスタムプロバイダは使えません（組み込みプロバイダを使ってください）。

05Runtime — v1 と v2

runtime input で OpenCode の世代を選びます。どちらも「minimum-release-age（デフォルト 24h）以上前に公開された最新の安定版」を GitHub Releases から解決して正確なバージョンをインストールします。適格なリリースが無い・API が失敗した場合は、未検証のフォールバックを入れずに実行を失敗させます。

観点OpenCode v2

minimum-release-age は 7d で遅延を延ばし、0s で無効化できます。対応単位は s / m / h / d / w。ドラフト・プレリリース・他メジャーのバージョンは除外されます。

06Pull request reviews — 隔離された review-only 実行

opencode-review.yml は、通常の bot 実行とは別設計の「読み取り専用レビュー」です。レビューの振る舞い自体は同梱せず、pr-loop の pr-review skill を不変のコミット SHA で外部から取り込みます（旧来の同梱 /review-pr コマンドや専用エージェントは廃止済み）。

対象の限定

ドラフトでなく、bot でなく、信頼できるリポジトリ協力者が開いた PR のみが対象です。モデル選択によってこの制限は変わりません。

使い捨ての HOME

review-only 実行はランナーの一時ディレクトリ配下の使い捨て HOME（XDG パスも分離）を使い、終了時に片付けます。プロジェクト設定と外部 skill 探索は無効化され、OpenCode は新規インストールされます。

凍結された証拠

リポジトリ内容は checkout のファイルではなく、Git の blob（git/blobs/<SHA>）経由で読みます。checkout のシンボリックリンクがランナーの資格情報へ読み取りを誘導することはありません。

公開は COMMENT 1件のみ

上流 skill は base/head スナップショットを凍結し、根拠と照合した所見だけを、対象コミットに紐づく COMMENT レビューとして1件公開します。Approve・変更要求・マージ・リポジトリ変更は決して行いません。

制限付き API アダプタ

GitHub 操作はネイティブな pr-review-api ツール経由の構造化リクエストのみ。シェル式・任意の CLI フラグ・ファイル入力は受け付けず、不正なペイロードは fail-closed で拒否されます。

トークンの検証

公開前に App トークンの同一性を、未提出の pending review の作成／削除プローブで検証します。トークンはファイルに書かれず、出力にも現れません。

これは OS サンドボックスではありません。 レビューエージェントの制限は OpenCode のツール権限による境界です。信頼できるランナーで実行し、pull-requests: write は必要範囲に留めてください。v2 のレビュー経路が受け付ける prompt は空か /pr-review のみで、自由文のレビュー観点指定は runtime: v1 でのみ可能です（例: prompt: Focus on security and performance.）。review-only の v1 には OpenCode v1.2.14 以降が必要です。

直接 action から review-only を使う場合は review-only: 'true'、use-bundled-toolkit: 'true'（必須）、完全な pr-review-ref のコミット SHA、対象 PR の URL と head SHA が必要です。review-only 実行では OpenCode バイナリのキャッシュを使いません。

07Inputs リファレンス

action の全 inputs です。テキストで絞り込めます。Reusable workflows もほぼ同じ inputs を持ち、review 専用項目（review-only 等）は bot 側だけ、runs-on は reusable 側だけにあります。

Inputデフォルト説明

出力（outputs）: opencode-version / runtime / cache-hit。

Sakura AI Engine モデル同期

任意の同期 workflow が、チャット可能な Sakura AI Engine モデルを発見し、カタログに変化があれば PR を自動で開く／更新します。有効化には SAKURA_AI_ENGINE_API_KEY secret が必要です。PR 作成にはリポジトリ標準の GITHUB_TOKEN（contents: write / pull-requests: write）を使い、追加のトークン secret は不要です。ただし GITHUB_TOKEN が起こしたイベントでは新しい workflow は起動しないため、この同期 PR が pull_request workflow を自動でトリガーすることはありません。

Releases

リリース workflow は、対象ファイルに変更がある週の月曜 09:15 JST に自動実行され、手動では major / minor / patch を指定して実行できます。公開後はメジャーバージョンタグを更新し、SHA ピンを更新する PR を開きます。この「リリース → ピン更新 PR」の循環が、利用者側の SHA ピン留めを常に新鮮に保ちます。

08Security — トークンモードと信頼境界

GitHub トークンの渡し方は2モードあり、トレードオフがはっきり分かれます。

デフォルト

OIDC → App トークン交換

use-github-token: false。workflow の OIDC トークンを OpenCode GitHub App トークンに交換します（id-token: write 必須）。v2 では App トークンも OIDC 資格情報も OpenCode 本体やその子プロセスには渡らず、ランチャーがメモリ内に保持します。gh は未認証です。

明示的に有効化

Workflow トークンを使う

use-github-token: true。コードを書かせる実行（git push）はこちらが必要です。ただし token mode では永続化された checkout 資格情報が OpenCode のシェルから読める状態にあり、トークンはモデルに隔離されていません。最小権限に絞ってください。

  1. 未検証のフォールバックを入れないRuntime 解決で適格な安定版が無い・Releases API が失敗した場合は、推測で入れずに実行を失敗させます。
  2. 公開は検証済みトークンでのみレビュー公開の既定経路は、同一性プローブを通過した OpenCode App トークンが必須です。不在・不一致は fail-closed です。
  3. トークンを残さないApp トークンはファイルに書き出されず、action の出力にも含まれません。v2 ランチャーはメモリ内でのみ保持します。
  4. トリガーの信頼ゲートbot のレビューコメント受理は OWNER / MEMBER / COLLABORATOR ＋ mentions 一致の両方が必要です（action を直接呼ぶ場合は呼び出し側の責任でゲートしてください）。
  5. Reusable workflow の権限上限呼び出し先は contents: read を上限とし、呼び出し側がより強い権限を持っていても引き上げられません。別途渡す GH_TOKEN はこの上限の対象外です。
  6. Review は読み取り専用が既定review-only のエージェントはデフォルト拒否で、skill・信頼済み参照の読み取り・ネイティブ API ツールだけを許可します。フォーマッタや言語サーバも無効化されます。
